# Dwell architecture

Three layers, one job each.

```text
01 Home/     use it
02 Notes/    keep the work
03 System/   explain and operate it
```

`Supernote/EXPORT/` is an intake folder. It is not where knowledge lives.

## Home

Dashboard, Hessel, Tasks, Notes, Review, and System are small action surfaces. They link to the next useful place rather than attempting to summarize the whole business. Bases provide portfolio and relationship views. The Tasks plugin provides checkbox queries; if a task block renders as code, install or enable Tasks on that device.

## Notes

Every substantive work note lives in `02 Notes/`, regardless of whether it is a property, person, meeting, project, procedure, field note, or resource. Its frontmatter `type` tells Bases how to surface it. A `property` link connects related work without filing the same material twice.

## System

`03 System/` contains the things that make the vault predictable: templates, scripts, inboxes, retained sources, logs, Bases, and these documents. It is readable documentation, not a second work area.

## Boundaries

- Dwell holds employer work. gOS holds personal knowledge and writing.
- The original transcript, image, PDF, or typed note remains the source. AI notes point back to it.
- Dwell can preserve context, prepare handoffs, and draft work. It does not send, publish, move money, or decide company commitments without Graham naming the action.
- Asana will hold execution work once adopted. Dwell remains the source and thinking layer.

## Current dependencies

Grain intake, Drive routing, scheduled nightly processing, and screen control are not assumed live merely because their files exist. Their current state and dates are in [[03 System/Documentation/ROADMAP|Roadmap]].
